# Analytics v1 — definitions fixed before UI implementation

All money is integer AED fils. Calendar days are Asia/Dubai (UTC+04:00), inclusive date filters, maximum 366 days. Previous period has the same number of calendar days immediately before the selected period. Zero comparison denominator means unavailable, never infinity. Financial date is first recorded authoritative payment confirmation (`Payment.paidAt`, or stored `Order.paidAt` with a warning), not order creation, delivery date or provider settlement date.

| Metric | Source / calculation | Inclusion / exclusion | Quality |
|---|---|---|---|
| Confirmed captured payment volume | Sum `Payment.amountFils` once per accepted payment identity | Paymennt, settled status paid/refunded/partially_refunded/chargeback, provider checkout reference, valid reconciliation and paid timestamp. Missing proof, mock, known TEST URLs, duplicate/conflicting identities and multiple settled attempts for one order are excluded with counts. Cancelled fulfillment does not erase a confirmed capture. | Partial whenever quarantined data exists. Gross historical captures, NOT net sales, settlements, profitability or cash available. |
| Paid orders | Distinct orders represented by the eligible captures | Same financial date/evidence rules; includes subsequently refunded/disputed orders | Same limitations as captures |
| Average captured order value | Capture volume / paid orders, rounded to nearest fils | Null for zero orders | Same limitations |
| Units / SKU volume | Quantity and accepted unit price from `Order.lines`, `Order.catalogSnapshot`, validated premium `priceSnapshot` | Entire order allocation must reconcile subtotal, fee and captured total; snapshot IDs unambiguous, integer quantity, valid preparation. Packs count purchased boxes, never nested components as separate sales. | Missing/inconsistent snapshots stay captured but explicitly unallocated, never reconstructed from current catalog |
| Product allocation / delivery fees | Sum quantity × immutable accepted unit price; fee separately | Only fully reconciled snapshots | Unknown fees/units are null if no allocatable order; known partial totals labeled partial |
| Product names/categories | Exact immutable catalog snapshot fields, grouped by SKU AND recorded definition/category | Current catalog, translations, eligibility, prices and media are never consulted | Historical category absent = unclassified. Family and size dimensions unavailable if not stored. No SKU-name heuristics |
| Order state / pickup / delivery | Current stored state and fulfillment on confirmed paid-date cohort | This is a current-state breakdown, not a historical state at end of period. Missing method = unknown | No invented stage duration or conversion rate |

| Profit / conversion / repeat customers / preparation duration | No adequate cost, visitor/session, identity or complete transition instrumentation | Not calculated | Unavailable |

## Financial audit and provenance

`CommerceService.applyCheckout` validates provider reference, request, order, amount and currency before writing `lastReconciledAt`, `paidAt` and the state. `paidAt` is local receipt time, not bank settlement time. Older webhook records can lack this evidence. Reporting deliberately does not promote payment status alone into verified revenue. There is no refund amount ledger, branch/tenant attribution, explicit payment environment marker or order creation field. Mock providers and known test-hosted URLs are excluded; unknown historical environment is disclosed, not claimed LIVE-verified. Runtime profile isolates test databases but cannot prove provenance of every old row.

Reporting does not call reconciliation, providers, commands, notifications or Store.write. It reads one consistent serialized SQLite state snapshot via Store.read. Source data remains immutable. Duplicate and missing records cause visible data-quality counts. No customer identity, address, notes, transaction IDs or checkout URLs leave the adapter. Product text is historical merchant-authored identification; CSV is escaped and formula-safe.
