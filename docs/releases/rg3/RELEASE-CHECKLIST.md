# Controlled release checklist — FUTURE AUTHORIZATION REQUIRED

## Before any main change

1. Close compiled route blocker on a reviewed corrective branch and integrate its exact SHA in the isolated RC.
2. Refresh all component/base/head SHAs; require full commercial, browser and compiled gates green on the exact final RC, no unexplained price or role changes.
3. Owner verifies private backup paths, completed timestamp, integrity, relationship baseline and isolated restoration; establishes RPO/RTO and custody of external secret files.
4. Obtain separate authorization for repository/deployment gating changes; verify Production autodeploy suspended or explicitly approval-gated, Wait for CI state, environment-scoped staged diff and no unrelated changes. Do NOT merge first and inspect settings later.
5. Record current live SHA/deployment, private counts/fingerprints/timestamps and rollback availability. Set a staffed change window and operator owner. No database copies in chat/GitHub.
6. Founder approves exact scope, merge action, resulting artifact verification and subsequent deployment as separate controlled actions. No synthetic LIVE payment or catalog import authorized by those actions unless explicitly included.
7. Under that authorization only, merge/revalidate resulting main and runtime builder/Node; deploy exact tested artifact with existing variables/volume unchanged. Keep catalog/printing/Google/Meta/Resend activation out of scope.

## GO / NO-GO

GO requires route200/auth/refresh for all eight paths, green exact-head gates, verified restorable live backup, approved gated pipeline, compatible persistent data and authorized Founder release. Any route404, wrong revision, auth exposure, invalid financial snapshot, unexplained counts, missing backup or unverified trigger is NO-GO.
