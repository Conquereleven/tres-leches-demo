# Operator guide

Open the existing Operations Inbox and select a conversation. The agent panel shows mode, state, intent/confidence, handoff reason and the latest private proposal. NOT_CONFIGURED means there is no active model connection; it is not a simulated success.

1. Take human control before approving a proposal. This assigns the conversation to you and cancels pending AI automation.
2. Generate or regenerate a private suggestion. Review the response and tool results. Edit customer text if necessary, then approve and send. The original WA1/WA2/WA3 mapping is preserved.
3. Review each proposed commercial action separately. Creating a draft, changing items or location and requesting payment all require explicit approval. The payment card shows authoritative amount, zone, minimum and delivery fee/free delivery. Approval uses the existing order service.
4. Reject a proposal to stop its remaining actions. Rejection does not undo actions already approved. If another operator or domain data changed, regenerate from the current state.
5. Pause AI to stop automation, or return control explicitly after review. Copilot remains the pilot default. A takeover cannot recall a message already dispatched to WhatsApp.
6. For a custom cake, review the enquiry and collect missing date, servings, theme, preferences, reference material and requirements. A human must quote. For payment proof, verify the normal payment reconciliation timeline; never treat a screenshot as paid.

The administrator can edit and approve knowledge by topic/language in the existing readiness panel. Leave unknown answers unapproved. A closed WhatsApp service window requires an approved template; free-form AI approval is blocked and a clear recoverable error is shown.
